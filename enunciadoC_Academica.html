Enunciado C: Sistema de Recomendación Académica

Modela, implementa y prueba una plataforma que recomienda materias electivas a estudiantes según su historial. Aplica herencia, polimorfismo, encapsulamiento, abstracción y las cuatro relaciones UML sobre listas int[] y ArrayList.

Java plano IntelliJ IDEA JUnit Git POO
01

Descripción del problema

Contexto y requerimientos funcionales

Una universidad desea recomendar materias electivas a sus estudiantes según su historial académico. Cada plan de estudios está compuesto por varias materias (obligatorias, electivas o nivelatorias), y cada facultad agrupa varios planes. Los estudiantes se asocian a los cursos que van cursando, y un recomendador sugiere electivas según su desempeño previo.

La plataforma debe poder consultar:

  • El promedio de notas de cada estudiante.
  • Las materias del plan de estudios de una facultad.
  • Recomendaciones personalizadas de electivas.

Requerimientos funcionales

  1. Existen tres tipos de curso: CursoObligatorio, CursoElectivo y CursoNivelatorio, todos heredan de una clase abstracta Curso.
  2. Cada estudiante registra sus notas en un int[] de capacidad fija.
  3. Un PlanEstudios posee cursos (composición: se crean dentro del plan).
  4. Una Facultad agrega varios planes (agregación).
  5. Un Recomendador depende de HistorialAcademico para generar sugerencias.
  6. Un Estudiante se asocia a cursos (relación N:M).
  7. La Facultad gestiona sus planes con ArrayList<PlanEstudios>.
02

Relaciones UML obligatorias

Debes respetar el contrato de diseño dado por el docente

El docente ya entregó el diagrama UML final en docs/UML-final.md. Tu código debe respetar exactamente las clases, atributos, métodos y las cinco relaciones:

RelaciónClases involucradasCómo se implementa
HerenciaCurso → CursoObligatorio, CursoElectivo, CursoNivelatorioClase abstracta Curso + @Override en subclases.
ComposiciónPlanEstudios ◆— CursoLos cursos se instancian dentro del constructor del plan.
AgregaciónFacultad ◇— PlanEstudiosLos planes se crean fuera y se registran con agregarPlan().
AsociaciónEstudiante — Curso (N:M)Referencia por atributo ArrayList<Curso>.
DependenciaRecomendador ⇢ HistorialAcademicoSe pasa como parámetro, no se guarda como atributo.
Contrato de diseño: no agregues ni elimines clases. Las firmas de los métodos ya están dadas en el código base; tu tarea es implementar sus cuerpos.
03

Qué debes implementar

Tareas concretas para la Sesión 2

Notas en Estudiante

Implementa registrarNota(int) con int[] de capacidad fija y promedio(). Si el arreglo se llena, no se registra la nota adicional.

Dificultad por tipo de curso

En cada subclase implementa dificultadEsperada() con lógica distinta (obligatorio, electivo, nivelatorio).

Composición en PlanEstudios

El constructor crea internamente los cursos del plan y los agrega a ArrayList<Curso>.

Agregación en Facultad

Implementa agregarPlan(PlanEstudios) usando ArrayList<PlanEstudios>.

Asociación en Estudiante

Implementa inscribirCurso(Curso) guardando la referencia en ArrayList<Curso>.

Dependencia en Recomendador

Implementa recomendar(HistorialAcademico h) recibiendo el historial como parámetro.

⚠ No modifiques la carpeta test/. Contiene las pruebas JUnit que usarás para verificar tu implementación. Cualquier modificación anula el examen.
El proyecto compila desde el primer minuto. Los métodos con TODO retornan valores neutros.
04

Indicaciones de Git

Clona, ramifica, commitea y sube

1. Clonar el repositorio base

git clone <URL-del-repo-base> parcial-estructuras
cd parcial-estructuras

2. Crear tu rama personal

git checkout -b parcial/nombre-apellido

3. Verificar que compila antes de tocar código

Abre el proyecto en IntelliJ y ejecuta Build → Rebuild Project. Debe compilar sin errores.

4. Commits atómicos sugeridos

# Al responder las preguntas de comprensión
git add docs/comprension.md
git commit -m "comprension: respondo preguntas del UML"

# Al implementar notas del estudiante
git add src/personas/Estudiante.java
git commit -m "impl: registro de notas y promedio"

# Al implementar dificultad por tipo de curso
git add src/cursos/
git commit -m "impl: dificultadEsperada en obligatorio, electivo y nivelatorio"

# Al implementar composición, agregación, asociación y dependencia
git add src/plan/ src/facultad/ src/servicios/
git commit -m "impl: relaciones UML completas"

# Al terminar
git add .
git commit -m "impl: TODOs completados y tests pasando"

5. Subir tu rama

git push origin parcial/nombre-apellido

6. Entrega

Publica en el aula virtual el enlace a tu rama antes del cierre de la sesión.

Buenas prácticas: commits pequeños y descriptivos; nunca subas out/ ni .class; no hagas force push.
05

Cómo ejecutar el proyecto

Desde la descarga hasta ver Main corriendo en IntelliJ
Paso 1
Clonar el repositorio

Usa el comando de la sección 04. Se creará la carpeta parcial-estructuras/.

Paso 2
Abrir en IntelliJ IDEA

File → Open… y selecciona la carpeta raíz del proyecto clonado.

Paso 3
Marcar src como Sources Root

Clic derecho sobre src → Mark Directory as → Sources Root.

Paso 4
Marcar test como Test Sources Root

Clic derecho sobre test → Mark Directory as → Test Sources Root.

Paso 5
Descargar el JAR de JUnit

Descarga junit-platform-console-standalone-1.10.2.jar desde repo1.maven.org y guárdalo en lib/.

Paso 6
Agregar JUnit como librería

File → Project Structure → Libraries → + → Java y selecciona el JAR. Verifica en Modules → Dependencies.

Paso 7
Recompilar el proyecto

Build → Rebuild Project. Debe terminar sin errores.

Paso 8
Ejecutar Main

Abre src/Main.java y haz clic en el triángulo verde junto a main.

Atajo alterno por terminal:
mkdir -p out
find src -name "*.java" > sources.txt
javac -d out @sources.txt
java -cp out Main
06

Cómo ejecutar las pruebas

Verifica tu implementación con los tests JUnit

Opción A · Desde IntelliJ (recomendado)

  1. Expande la carpeta test/ en el panel de proyecto.
  2. Clic derecho sobre test → Run 'All Tests'.
  3. IntelliJ mostrará el árbol de resultados en verde o rojo.
  4. Si un test falla, haz clic para ver el AssertionError.
  5. Itera hasta que todos queden en verde.

Opción B · Desde la terminal

mkdir -p out
find src test -name "*.java" > sources.txt
javac -cp lib/junit-platform-console-standalone-1.10.2.jar -d out @sources.txt

java -jar lib/junit-platform-console-standalone-1.10.2.jar \
     --class-path out --scan-class-path

Qué evalúan los tests

Archivo de testQué verifica
EstudianteTest.javaRegistro de notas en int[], promedio y asociación con cursos.
CursoTest.javaDificultad esperada por tipo y polimorfismo.
PlanEstudiosTest.javaComposición: los cursos se crean dentro del plan.
FacultadTest.javaAgregación de planes.
RecomendadorTest.javaDependencia con HistorialAcademico.
Recuerda: los tests comprueban el comportamiento esperado. Si fallan, el problema está en tu implementación. No modifiques los tests.
